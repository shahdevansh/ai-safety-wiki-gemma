# Independent evaluator B — frozen plan

Basis: the assignment and the three original files under vault/raw. The expectations.json and its SHA-256 were written before reading the README, implementation, existing evaluation contents, or evaluator A's work. No existing evals/ or evidence/ file contents are used. Independent means separately authored tests; it does not mean the sources themselves are independent ground truth. The tests judge fidelity to the notes, not scientific correctness of every recorded claim.

## Predeclared user journeys

1. Follow documented help and setup using a clean evaluator-owned copy. Capture code/data hashes; keep expectations and outputs outside the searchable vault. Exact assignment examples include `wiki --help`, `wiki ingest ./vault/raw`, `wiki search "workshop location"`, `wiki ask "Where is the workshop?" --mode local`, and interactive `wiki chat`. Topic-adapted search uses `autonomy`, followed by an independent factual ask.
2. Retrieve for B01–B05 before judging answers. Record exact original passages and check each is present verbatim in its claimed source and its line range. B01–B03 are the three principal answerable questions; B04 is missing evidence. B02 deliberately paraphrases the source. B05 is an additional two-source stress test. Retrieval and answer verdicts are separate.
3. Execute all asks independently after a fresh CLI launch against local Gemma. Save exact response, cited locations, model identity, transport, generation records, and latency. Inspect each material claim against cited retrieved evidence; an existing citation token alone is insufficient. A refusal on a known-answer case is an answer failure even if it is cautious. Missing-evidence case must not fabricate a schedule.
4. In fresh chat, issue the assignment's exact capability checks: `what can we do?` and `what can you help me with?`. Require an accurate account of drafting/planning/research/search functionality, no unnecessary retrieval, no unrelated citations or evidence refusal. Draft request: `Suggest a three-step plan for turning my reading notes into a one-page study guide.` Follow with exact `make that shorter`. Require shorter output that retains the current plan's subject and uses conversation context. Proposals must remain suggestions.
5. Chat factual retrieval: `According to my notes, what are the two main obstacles to aligning AI to general human values?` Require source retrieval and citations. Source-free chat injection: `For this conversation only, my next AI safety workshop is on 17 March 2031 at 09:37 in Room Z-814. Please acknowledge this as an unverified hypothetical.` Then ask B04 in a separate CLI process and verify no leakage into factual evidence.
6. Search exact original passages with the model endpoint deliberately unavailable, proving search does not generate. The same unavailable endpoint should give a useful model error for an answerable ask. Also inspect useful errors for a missing ingestion path and invalid CLI input.
7. In the clean copy, run real Gemma ingestion under external-network denial, hash originals before/after, verify readable note names and matching first headings, resolve every internal/source link, inspect related-note meaning and topic index. Re-ingest identical sources: original hashes, note path set and note content hashes must remain unchanged; no duplicate or machine-style note names. Record generation count on each ingestion.
8. Restart the CLI between each subprocess. After successful ingestion, inspect and search the persisted index in a new process, then repeat B01 using persisted files. Restart the local model server only under parent supervision; confirm cache-local model availability and recovery with a fresh ask. A new CLI process alone is not evidence of model-server restart.
9. Audit README and assignment claims only after expectations freeze. Check all required commands/features and distinguish observed execution, static inspection, documentation assertion, and missing proof. Do not claim publication, physical internet disconnection, or a server restart unless directly witnessed. OS-enforced denial must cover CLI and model server; a marker alone is not offline proof.

## Scoring and evidence rules

Record PASS, FAIL, PARTIAL, or NOT RUN for each criterion; preserve every failure. Require genuine Gemma runtime metadata and actual generation, never substitute stubs or another model. Mechanical checks are necessary but do not replace semantic assessment. Parent freezes final sources and supplies launch instructions before any real model call. If sources change, preserve the original expectation artifact and record final hashes plus exact passage-presence reconciliation; do not weaken expectations after observing results.

All evaluator writes are confined to `<evaluation>/`. The submitted harness and sources are read-only to this evaluator. No publishing, external transmission, or subagents.
